# Software Requirements Specification: traceability

This table maps every requirement from the project brief to the code and tests that
satisfy it. Rows marked *planned* point to the phase that will deliver them.
Updated at the end of every phase.

## Functional requirements

| ID | Requirement | Where it is covered | Tests |
|---|---|---|---|
| FR-1 | Users must log in with username and password before accessing any module. | `require_login` in `app/__init__.py` protects every endpoint except login, sign-up and health; `AuthService.login()` in `app/services/auth_service.py` (generic error, 5 failures = 15-minute lockout, inactive accounts blocked); `auth` controller in `app/controllers/auth.py`; bcrypt in `app/auth/passwords.py`; rate limit 10/min on login. | `tests/unit/test_auth_service.py`, `tests/integration/test_auth_flow.py::test_anonymous_user_is_sent_to_login`, `::test_five_failures_lock_the_account_and_write_an_audit_entry`, `::test_inactive_account_cannot_log_in`, `tests/e2e/test_login.py` (Playwright, CSRF on) |
| FR-2 | Role-based access control (Admin vs Volunteer). | Roles are reference data in `database/schema.sql`; `Person.is_admin` in `app/models/person.py`; `UserDAO.to_model()` returns `Admin` or `Volunteer`; `role_required` route decorator and `require_role()` service check in `app/auth/roles.py`; `/volunteer/*` and `/admin/*` controllers each require their role. | `tests/unit/test_roles.py`, `tests/unit/test_dao.py::test_user_dao_builds_admin_without_profile`, `tests/integration/test_auth_flow.py::test_volunteer_logs_in_and_reaches_only_the_volunteer_dashboard`, `::test_admin_logs_in_and_reaches_only_the_admin_dashboard` |
| FR-3 | Authorized users can Create, Read, Update and Delete core records. | DAO write methods in `app/dao/` (`insert`, `update`, `delete`, `set_status`). | FR-4 | All input is validated before it is saved. | Pydantic `SignUpSchema` / `LoginSchema` in `app/schemas/auth.py` run through `validate()` in `app/schemas/base.py` (one message per field, shown inline by `partials/_forms.html`); `ProfileSchema` / `ChangePasswordSchema` in `app/schemas/profile.py` (phone shape, birth date in the past and 13+, new password must differ from the current one and, like sign-up, follows `check_password_strength()`: letter + number, at most 72 bytes for bcrypt); `check_photo()` in `app/services/profile_service.py` checks extension, magic bytes and size, and `MAX_CONTENT_LENGTH` gives a friendly 413 page; `Activity.validate()` in `app/models/activity.py`; database CHECK constraints in `database/schema.sql`. Later phases add a schema per form. | `tests/unit/test_schemas_auth.py`, `tests/unit/test_schemas_profile.py`, `tests/unit/test_profile_service.py`, `tests/integration/test_auth_flow.py::test_signup_with_invalid_input_shows_errors_and_saves_nothing`, `tests/integration/test_profile_flow.py::test_edit_profile_with_invalid_input_shows_errors_and_saves_nothing`, `::test_bad_photo_is_rejected_with_a_message`, `::test_oversized_upload_gets_a_friendly_413_page`, `tests/unit/test_models.py::test_activity_validate_rejects_bad_rules`, `tests/integration/test_database.py::test_check_constraint_becomes_validation_error` |
| FR-5 | All core data is stored in MySQL served through XAMPP. | `database/schema.sql` (8 InnoDB tables); `app/database/db_manager.py`; `scripts/init_db.py`. | `tests/integration/test_database.py::test_schema_has_all_tables_with_innodb_utf8mb4` |
| FR-6 | Every add/edit/delete is recorded in an audit trail. | `audit_logs` table; `AuditLogDAO` in `app/dao/audit_log_dao.py`. Phase 1 writes `SIGN_UP` and `ACCOUNT_LOCKED` entries (`AuthService`). ## Non-functional requirements

| Quality | Requirement | Where it is covered |
|---|---|---|
| Usability | Main actions within 2 clicks of the dashboard, no manual needed. | `templates/base.html` header + sidebar (`app/navigation.py` builds the menu per role); both dashboards link straight to each action. Phase 2: My Profile is one click from the sidebar or the dashboard card; Edit, Change Password and Change Photo are one more click. Later phases add the remaining pages. |
| Reliability | Full 15-minute demo without unhandled crashes. | Typed errors + global handlers (`app/__init__.py`); reconnect in `DatabaseManager.connection()`. *Phase 9* demo checklist. |
| Performance | CRUD on 1,000 records within 2 seconds. | Indexes on every FK and on `activity_date`, `status`, `title`, `timestamp` (`database/schema.sql`); `LIMIT/OFFSET` pagination in `ActivityDAO.search()`; `python seed.py --big` creates 1,000 activities for the check. |
| Security | No plain-text passwords; all SQL parameterized. | bcrypt cost 12 in `app/auth/passwords.py`; every DAO uses `%s` placeholders (`tests/unit/test_dao.py::test_user_dao_insert_sets_id_and_binds_values` proves injection text stays a parameter); `Person.to_dict()` strips the hash. |
| Maintainability | Modules: models, views, controllers, dao, database; PEP 8 naming. | Folder layout in `README.md`; `ruff` enforces PEP 8 (`N` rules) and `mypy --strict` checks types in CI. |
| Portability | Runs on any machine with Python 3 and XAMPP via the README; no hard-coded paths. | All settings come from `.env`; `scripts/init_db.py` and `scripts/tailwind.ps1` use relative paths. |

## Required design patterns

| Pattern | Class / file | Test that exercises it |
|---|---|---|
| Singleton | `DatabaseManager` in `app/database/db_manager.py` | `tests/unit/test_db_manager.py::test_singleton_returns_the_same_instance` |
| MVC | `app/models/`, `app/templates/`, `app/controllers/` | `tests/integration/test_database.py::test_health_endpoint_reaches_database` |
| Inheritance | `BaseEntity` -> `Person` (abstract) -> `Volunteer`, `Admin` in `app/models/` | `tests/unit/test_models.py::test_person_cannot_be_instantiated_directly` |
| Polymorphism | `Person.generate_report()` overridden by `Volunteer` and `Admin` | `tests/unit/test_models.py::test_volunteer_generate_report_counts_own_hours`, `::test_admin_generate_report_gives_system_totals` |
| Template Method | `BaseReport.generate()` in `app/services/reports/base_report.py` | `tests/unit/test_reports.py::test_generate_runs_steps_in_fixed_order` |
| DAO | One class per table in `app/dao/` | `tests/unit/test_dao.py` (happy + failure per DAO) |
